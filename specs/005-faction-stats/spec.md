# Feature Specification: 势力统计排行榜

**Feature Branch**: `005-faction-stats`  
**Created**: 2025-12-01  
**Status**: Draft  
**Input**: User description: "在005-stats 分支，新增一个功能，可以统计各个势力拥有的国家数量和国土面积。以国家数量为排行依据"  
**Update**: 增加战胜和战败次数统计

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 查看势力综合排行榜 (Priority: P1)

玩家在游戏进行过程中，想要了解当前各个势力（指挥官）的实力对比，可以查看一个清晰的排行榜，显示每个势力的多维统计数据：
- 占领的国家数量（主要排序依据）
- 国土总面积
- 战胜次数（进攻成功次数）
- 战败次数（防守失败次数）
- 胜率（战胜次数 / 总战斗次数）

**Why this priority**: 这是核心功能，提供了游戏进程的全局视角和多维度数据，让玩家能够全面了解战局态势、势力实力和战斗表现，是最基本和最重要的需求。

**Independent Test**: 可以通过启动游戏、触发多次战斗（包括成功和失败）、打开统计面板来独立测试，验证排行榜是否正确显示所有活跃势力及其完整统计数据。

**Acceptance Scenarios**:

1. **Given** 游戏正在运行且有多个活跃指挥官, **When** 玩家打开统计面板, **Then** 显示所有活跃势力的排行榜，按国家数量降序排列，同时显示面积、战胜、战败和胜率数据
2. **Given** 某个势力占领了新的国家, **When** 排行榜自动或手动刷新, **Then** 该势力的国家数量、面积和战胜次数更新，排名可能变化
3. **Given** 某个势力在防守战中失败, **When** 排行榜刷新, **Then** 该势力的战败次数增加，胜率重新计算
4. **Given** 某个势力被消灭（失去所有领土）, **When** 排行榜刷新, **Then** 该势力从排行榜中移除或标记为已淘汰，并保留其最终战绩
5. **Given** 排行榜显示中, **When** 多个势力国家数量相同, **Then** 按照国土总面积降序作为次要排序依据
6. **Given** 某个势力尚未参与任何战斗, **When** 查看排行榜, **Then** 显示战胜/战败次数为0，胜率显示为"N/A"或"-"

---

### User Story 2 - 实时更新排行榜 (Priority: P2)

当游戏中发生领土变更时，排行榜数据能够自动或半自动更新，玩家无需手动刷新即可看到最新的势力对比。

**Why this priority**: 提升用户体验，避免玩家频繁手动刷新，让统计数据始终保持准确性。这是在基本功能之上的体验优化。

**Independent Test**: 可以通过观察多次战斗后排行榜数据的变化来测试，验证是否能够捕获领土变更事件并更新统计。

**Acceptance Scenarios**:

1. **Given** 排行榜面板已打开, **When** 某个势力占领或失去领土, **Then** 排行榜在合理时间内（如1-2秒）自动更新
2. **Given** 排行榜面板未打开, **When** 玩家重新打开面板, **Then** 显示最新的统计数据

---

### User Story 3 - 查看势力详细统计 (Priority: P3)

玩家可以点击排行榜中的某个势力，查看该势力的详细信息，包括：
- 占领的具体国家列表及各自面积
- 战斗历史记录（最近的战胜/战败事件）
- 进攻成功率和防守成功率的分别统计
- 时间趋势图（如领土变化曲线、战斗活跃度等）

**Why this priority**: 提供更深入的信息探索能力，满足玩家深度了解特定势力战斗表现和发展历程的需求。这是可选的增强功能。

**Independent Test**: 可以通过点击排行榜中的势力条目来测试，验证是否能正确显示该势力的详细统计信息和战斗历史。

**Acceptance Scenarios**:

1. **Given** 排行榜显示中, **When** 玩家点击某个势力, **Then** 展开或弹出该势力的详细统计面板，显示完整战绩
2. **Given** 详细统计面板显示中, **When** 玩家查看国家列表, **Then** 显示该势力占领的所有国家名称和各自面积
3. **Given** 详细统计面板显示中, **When** 玩家查看战斗历史, **Then** 显示最近的战斗事件列表，包括对手、结果和领土变化
4. **Given** 详细统计面板显示中, **When** 玩家查看分项统计, **Then** 显示进攻成功率和防守成功率的单独计算结果
5. **Given** 详细统计面板显示中, **When** 玩家关闭面板, **Then** 返回到排行榜主视图

---

### Edge Cases

- 游戏开始时，所有势力国家数量为0，如何显示初始状态？
  - **处理方式**: 显示所有势力，国家数量和面积均为0，按照势力ID或名称排序
  
- 某个势力被消灭后，是否还在排行榜中显示？
  - **处理方式**: 从活跃排行榜中移除，或显示为"已淘汰"状态
  
- 当只剩一个势力时（游戏胜利），排行榜如何显示？
  - **处理方式**: 仅显示该胜利势力，或显示所有势力但标记胜利者
  
- 当国家数据（面积）缺失或异常时，如何处理？
  - **处理方式**: 使用默认值0，或标记为"数据不可用"
  
- 排行榜在游戏暂停时是否可访问？
  - **处理方式**: 可以访问，显示暂停时刻的快照数据
  
- 战斗次数如何定义？是否包括占领中立领土？
  - **处理方式**: 仅统计与其他势力的战斗，不包括占领无主领土的行为
  
- 胜率计算中，总战斗次数为0时如何处理？
  - **处理方式**: 显示为"N/A"或"-"，避免除以零错误
  
- 是否区分进攻战斗和防守战斗的统计？
  - **处理方式**: 基础排行榜显示总战胜/战败，详细面板中分别统计进攻成功率和防守成功率

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须收集并维护每个活跃势力的国家数量统计
- **FR-002**: 系统必须计算并维护每个活跃势力的国土总面积统计
- **FR-003**: 系统必须记录并统计每个势力的战胜次数（进攻成功导致占领领土的次数）
- **FR-004**: 系统必须记录并统计每个势力的战败次数（防守失败导致失去领土的次数）
- **FR-005**: 系统必须计算每个势力的胜率（战胜次数 / 总战斗次数），当总次数为0时显示为"N/A"
- **FR-006**: 系统必须按照国家数量降序排列势力，相同数量时按面积降序排列
- **FR-007**: 用户必须能够通过UI界面访问排行榜功能（如按钮、快捷键或菜单）
- **FR-008**: 排行榜必须显示每个势力的名称、国家数量、国土总面积、战胜次数、战败次数和胜率
- **FR-009**: 系统必须在战斗结果确定时更新参与势力的战胜/战败统计
- **FR-010**: 系统必须在领土所有权变更时更新相关势力的国家数量和面积统计
- **FR-011**: 系统必须区分与其他势力的战斗和占领中立领土，仅前者计入战胜/战败统计
- **FR-012**: 当势力被消灭时，系统必须更新排行榜，移除或标记该势力，并保留其最终战绩
- **FR-013**: 排行榜必须区分活跃势力和已淘汰势力
- **FR-014**: 用户必须能够关闭排行榜面板并返回游戏主视图
- **FR-015**: 系统必须在游戏开始时初始化所有势力的统计数据（所有数值为0）

### Key Entities

- **势力统计 (Faction Statistics)**: 
  - 代表单个势力的综合统计数据
  - 关键属性：
    - 基础信息：势力ID、势力名称、状态（活跃/已淘汰）
    - 领土统计：占领国家数量、国土总面积（平方公里）
    - 战斗统计：战胜次数、战败次数、总战斗次数、胜率
    - 排名信息：当前排名位置
  - 与指挥官（Commander）实体关联：通过指挥官ID关联
  - 与国家（Country）实体关联：通过占领关系计算领土统计
  - 与战斗事件（BattleEvent）实体关联：通过战斗记录统计战胜/战败

- **战斗记录 (Battle Record)**:
  - 代表单次战斗的结果（用于统计）
  - 关键属性：战斗ID、时间戳、进攻方ID、防守方ID、结果（成功/失败）、涉及领土ID
  - 用于追溯战斗历史和计算战绩统计

- **排行榜 (Leaderboard)**:
  - 代表势力统计的排序列表
  - 关键属性：统计快照时间、势力统计列表、排序规则（主要：国家数量，次要：面积）
  - 与势力统计关联：包含多个势力统计记录

## Quality Guardrails _(per Constitution)_

- **Code Quality**: 
  - 统计计算逻辑必须有清晰的单元测试
  - UI组件必须遵循项目的组件规范和样式指南
  - 代码必须通过 TypeScript 严格模式检查和 ESLint 验证
  - 必须添加必要的注释说明统计算法和数据流

- **Testing Evidence**: 
  - **TS-US1**: 排行榜显示与排序逻辑的单元测试（覆盖率 ≥ 90%）
  - **TS-US2**: 战斗结果触发战胜/战败统计更新的集成测试
  - **TS-US3**: 领土变更触发国家数量和面积统计更新的集成测试
  - **TS-US4**: 胜率计算逻辑的单元测试（包括除以零情况）
  - **TS-US5**: 势力详细信息展示的UI测试
  - **TS-Edge**: 边界情况测试（空数据、单势力、势力消灭、零战斗次数等）
  - 所有测试必须在 CI 管道中自动执行

- **User Experience**: 
  - 排行榜必须在500ms内完成渲染（性能指标）
  - 数据更新必须有视觉反馈（如动画或高亮变化项）
  - 面板打开/关闭必须有流畅的过渡动画
  - 支持键盘快捷键访问（可访问性要求）
  - 任务完成率目标：95%的玩家能在首次尝试时成功查看排行榜

- **Performance & Observability**: 
  - 统计计算必须在主游戏循环之外异步执行，避免阻塞渲染
  - 性能预算：统计计算 < 50ms（对于200个国家）
  - 当性能下降时，降级为手动刷新模式
  - 记录排行榜打开次数、停留时间等遥测数据
  - 记录统计计算时间和数据更新频率，用于性能监控

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 玩家能够在3秒内打开并查看完整的排行榜（包括所有统计维度）
- **SC-002**: 排行榜数据在战斗结束后2秒内完成更新（包括战胜/战败和领土统计）
- **SC-003**: 排行榜支持至少50个活跃势力的同时显示和排序，包含所有统计字段
- **SC-004**: 90%的玩家在首次使用时能够理解排行榜的排序逻辑和各项统计含义（通过用户测试验证）
- **SC-005**: 统计计算（包括战斗统计和领土统计）对游戏帧率的影响小于5%（维持60fps以上）
- **SC-006**: 战胜/战败统计的准确率为100%（与实际战斗结果完全一致）
- **SC-007**: 胜率计算的精度误差小于0.1%
- **SC-008**: 排行榜功能的崩溃率为0（在标准游戏流程中）
