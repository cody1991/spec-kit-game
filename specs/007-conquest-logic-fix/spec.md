# Feature Specification: 领主占领逻辑修复

**Feature Branch**: `007-conquest-logic-fix`  
**Created**: 2025-12-01  
**Status**: Draft  
**Input**: 用户描述："修复领主占领逻辑：1.每个领主一开始必须有国家，后面不会凭空出现；2.占领只能占领附近国家"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 领主初始化必须拥有国家 (Priority: P1)

作为玩家，我希望游戏开始时每个参与的领主都已经拥有至少一个国家，这样游戏的领土争夺才显得合理和真实。没有初始国家的领主不应该在游戏中出现或参与战斗。

**Why this priority**: 这是游戏逻辑的基础约束。如果领主可以凭空出现并占领国家，会破坏游戏的沉浸感和公平性，让玩家感到困惑。

**Independent Test**: 可以通过启动新游戏并验证所有活跃领主都有至少一个初始国家来独立测试。

**Acceptance Scenarios**:

1. **Given** 游戏初始化时有 N 个领主模板, **When** 世界创建完成, **Then** 每个活跃领主的 `controlledTerritories` 列表至少包含 1 个国家ID
2. **Given** 某个领主在初始化时未能分配到国家, **When** 世界创建完成, **Then** 该领主不会出现在活跃领主列表中（被排除或标记为非活跃）
3. **Given** 游戏运行过程中, **When** 检查所有活跃领主, **Then** 不存在任何"凭空出现"的新领主（领主数量只减不增）

---

### User Story 2 - 占领更倾向于相邻国家 (Priority: P1)

作为玩家，我希望领主在扩张时更倾向于占领与其当前领土相邻的国家，而不是随机跳跃到远处。偶尔的远距离占领可以存在（如海上远征），但大部分扩张应该是渐进式的、符合地理逻辑的。

**Why this priority**: 这是核心游戏玩法的合理性保障。倾向性约束让领土扩张更自然，玩家可以大致预测势力范围的变化趋势，同时保留一定的意外性和策略多样性。

**Independent Test**: 可以通过观察多轮战斗后，统计领土占领事件中相邻国家占领的比例来独立测试。

**Acceptance Scenarios**:

1. **Given** 领主A控制国家X, 国家Y与国家X相邻, **When** 领主A选择攻击目标, **Then** 相邻国家被选中的概率为 85%
2. **Given** 领主A控制国家X, 国家Z与国家X不相邻, **When** 战斗系统运行, **Then** 领主A有 15% 概率可以发起远程攻击
3. **Given** 领主A失去所有领土, **When** 该领主被淘汰后, **Then** 该领主不能再发起任何进攻或占领行为

---

### User Story 3 - 游戏过程中领主数量只减不增 (Priority: P2)

作为玩家，我希望游戏开始后不会有新的领主突然加入战局，只有被淘汰的领主会退出，这样游戏进程是可预测的。

**Why this priority**: 保证游戏的可预测性和公平性，玩家可以制定长期策略。

**Independent Test**: 可以通过记录游戏开始时的领主数量，并在游戏过程中验证数量只减不增来测试。

**Acceptance Scenarios**:

1. **Given** 游戏开始时有 N 个活跃领主, **When** 游戏进行 100 个 tick 后, **Then** 活跃领主数量 ≤ N
2. **Given** 领主A被淘汰（失去所有领土）, **When** 后续游戏继续, **Then** 领主A不会重新变为活跃状态

---

### Edge Cases

- 如果初始化时可用国家数量少于领主数量，如何处理？（假设：只创建与可用国家数量相等的领主）
- 如果一个领主的所有相邻国家都被同一个盟友控制，该领主如何扩张？（假设：可以攻击盟友或等待局势变化）
- 如果地图数据中某些国家没有相邻国家（如岛国），如何处理？（假设：这些国家只能被有海军能力的领主占领，或作为初始领土但不可扩张）

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须确保每个活跃领主在游戏开始时至少控制一个国家
- **FR-002**: 系统必须在初始化时排除未能分配到国家的领主（不将其加入活跃列表）
- **FR-003**: 系统必须使领主更倾向于攻击与其当前领土相邻的国家（85% 概率选择相邻目标）
- **FR-004**: 系统应允许 15% 概率的远程攻击，以保留策略多样性
- **FR-005**: 系统必须禁止在游戏运行过程中创建或激活新的领主
- **FR-006**: 系统必须在领主失去所有领土时将其标记为已淘汰，且不可恢复
- **FR-007**: 系统必须维护准确的国家相邻关系数据（`adjacentIds`）

### Key Entities

- **HistoricalCommander（领主）**: 游戏中的势力代表，拥有属性、技能和控制的领土列表。关键属性：`controlledTerritories`（控制的国家ID列表）、`status`（活跃/已淘汰）
- **Territory（领土/国家）**: 地图上的可占领单位，拥有相邻关系。关键属性：`adjacentIds`（相邻国家ID列表）、`ownerId`（当前控制者）
- **BattleSystem（战斗系统）**: 处理领土争夺的核心系统，需要执行相邻性验证

## Quality Guardrails _(per Constitution)_

- **Code Quality**: 修改 `createInitialWorld` 和 `BattleSystem` 时需保持现有代码风格，添加必要的注释说明相邻性验证逻辑
- **Testing Evidence**: 添加单元测试验证：1) 初始化后所有领主都有领土；2) 约 85% 战斗发生在相邻国家间；3) 领主数量只减不增
- **User Experience**: 玩家应能直观理解领土扩张的地理逻辑，大部分扩张是渐进式的，偶尔的远程占领增加游戏趣味性
- **Performance & Observability**: 相邻性检查应使用 O(1) 的 Map/Set 查找，不影响现有性能

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 游戏启动后，100% 的活跃领主拥有至少一个初始国家
- **SC-002**: 游戏运行过程中，约 85% 的领土占领事件发生在相邻国家之间
- **SC-003**: 游戏运行过程中，活跃领主数量只减不增（无新领主凭空出现）
- **SC-004**: 玩家在观察领土变化时，能够理解大部分占领的地理逻辑（领土扩张呈渐进式）

## Clarifications

### Session 2025-12-01

- Q: 相邻国家攻击的具体概率应该是多少？ → A: 85% 相邻（推荐平衡值）

## Assumptions

- 现有的 `adjacentIds` 数据是准确的，能够正确反映国家间的地理相邻关系
- 当前战斗系统已经使用相邻性逻辑（基于代码审查确认），但可能存在边界情况未处理
- 领主初始化时的国家分配逻辑可能在某些情况下失败，需要添加验证和排除机制
