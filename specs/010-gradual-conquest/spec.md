# Feature Specification: 渐进式领土蚕食机制

**Feature Branch**: `010-gradual-conquest`  
**Created**: 2025-12-01  
**Status**: Draft  
**Input**: User description: "现在的产品形态，是一个国家战胜，整个替换成胜利者的。有可能是一点点蚕食过去吗？直接还会有拉扯。可能是很难得一个任务。"

---

## 背景分析

### 当前机制

通过分析 `battleSystem.ts`，当前战斗系统采用**一次性完全占领**模式：

```typescript
// battleSystem.ts:234-238
this.batch.territories.set(territory.id, {
  ownerId: attacker.id,  // 直接更换所有者
  garrison: Math.floor(attacker.currentPower * 0.3),
  stability: Math.max(20, territory.stability - 30),
});
```

**问题**：
- 战斗胜利后，整个国家立即更换所有者
- 没有"拉锯战"或"争夺"的过程
- 大国和小国的占领难度相同
- 缺乏战略深度和紧张感

### 用户期望

用户希望实现：
1. **渐进式蚕食**：领土不是一次性被占领，而是逐步被侵蚀
2. **拉扯机制**：双方可以在边境地区反复争夺
3. **战略深度**：需要持续投入才能完全控制一个地区

---

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 观察渐进式领土蚕食 (Priority: P1)

作为玩家，我希望看到领土被逐步蚕食而非一次性占领，体验更真实的征服过程。

**Why this priority**: 这是本功能的核心体验，直接改变游戏的战斗表现形式。

**Independent Test**: 启动游戏，观察战斗胜利后领土是否显示"占领进度"而非直接更换颜色。

**Acceptance Scenarios**:

1. **Given** 势力A攻击势力B的领土X, **When** 战斗胜利, **Then** 领土X的"占领进度"增加（如从0%增加到30%），而非直接归属势力A
2. **Given** 领土X的占领进度为70%, **When** 势力A再次战斗胜利, **Then** 占领进度增加到100%，领土正式归属势力A
3. **Given** 领土X的占领进度为50%, **When** 势力B（原所有者）防守成功, **Then** 占领进度减少（如从50%降到30%）

---

### User Story 2 - 边境拉锯战 (Priority: P1)

作为玩家，我希望看到双方在边境地区反复争夺，形成紧张的拉锯战。

**Why this priority**: 拉锯战是渐进式蚕食的核心体验，让游戏更具戏剧性。

**Independent Test**: 观察两个实力相当的势力在边境的战斗是否出现进度反复变化。

**Acceptance Scenarios**:

1. **Given** 势力A和B实力相当, **When** 在边境领土X反复战斗, **Then** 占领进度应在30%-70%之间波动
2. **Given** 领土X占领进度为100%, **When** 原所有者B发起反攻并胜利, **Then** 占领进度开始下降（如从100%降到80%）
3. **Given** 占领进度从100%降到0%, **When** 进度归零, **Then** 领土归还原所有者

---

### User Story 3 - 领土大小影响占领难度 (Priority: P2)

作为玩家，我希望大国比小国更难被完全占领，体现真实的战略差异。

**Why this priority**: 增加战略深度，让大国更有防御优势。

**Independent Test**: 比较占领大国（如俄罗斯、中国）和小国（如新加坡）所需的战斗次数。

**Acceptance Scenarios**:

1. **Given** 攻击小国（面积<10万km²）, **When** 战斗胜利, **Then** 每次增加40%占领进度
2. **Given** 攻击中等国家（面积10-100万km²）, **When** 战斗胜利, **Then** 每次增加25%占领进度
3. **Given** 攻击大国（面积>100万km²）, **When** 战斗胜利, **Then** 每次增加15%占领进度

---

### User Story 4 - 视觉反馈显示占领进度 (Priority: P2)

作为玩家，我希望在地图上直观看到领土的占领进度。

**Why this priority**: 良好的视觉反馈是用户体验的重要组成部分。

**Independent Test**: 观察正在被蚕食的领土是否有明显的视觉变化。

**Acceptance Scenarios**:

1. **Given** 领土X正在被蚕食（进度50%）, **When** 查看地图, **Then** 领土显示混合颜色（攻击方和防守方颜色渐变）
2. **Given** 领土X占领进度为80%, **When** 查看地图, **Then** 攻击方颜色占主导，防守方颜色淡化
3. **Given** 领土X有占领进度, **When** 悬停该领土, **Then** 显示具体进度百分比

---

### User Story 5 - 稳定性衰减机制 (Priority: P3)

作为玩家，我希望被蚕食的领土稳定性下降，更容易被进一步占领。

**Why this priority**: 增强滚雪球效应，让进攻方有持续推进的动力。

**Independent Test**: 观察被多次攻击的领土稳定性是否持续下降。

**Acceptance Scenarios**:

1. **Given** 领土X稳定性为100%, **When** 被攻击且占领进度增加, **Then** 稳定性下降（如降到70%）
2. **Given** 领土X稳定性为30%, **When** 被攻击, **Then** 防御力降低，更容易被占领
3. **Given** 领土X被完全占领, **When** 一段时间无战斗, **Then** 稳定性逐渐恢复

---

### Edge Cases

- **当占领进度刚好达到100%时**：领土正式更换所有者，进度重置为0%
- **当占领进度降到0%时**：领土保持原所有者，攻击方需重新开始蚕食
- **当原所有者被淘汰时**：该势力所有领土的占领进度立即变为100%（无人防守）
- **当多个势力同时攻击同一领土时**：只有进度最高的攻击方可以继续蚕食
- **当领土无主时**：直接占领，无需蚕食过程

## Requirements _(mandatory)_

### Functional Requirements

#### 占领进度系统

- **FR-001**: 系统必须为每个领土维护"占领进度"属性（0-100%）
- **FR-002**: 系统必须在战斗胜利时增加占领进度，而非直接更换所有者
- **FR-003**: 系统必须在占领进度达到100%时正式更换领土所有者
- **FR-004**: 系统必须在防守成功时减少攻击方的占领进度

#### 进度计算规则

- **FR-005**: 系统必须根据领土面积计算每次战斗的进度变化量
  - 小国（<10万km²）：每次+40%/-30%
  - 中国（10-100万km²）：每次+25%/-20%
  - 大国（>100万km²）：每次+15%/-12%
- **FR-006**: 系统必须根据攻击方与防守方的实力差距调整进度变化
  - 攻击方实力是防守方2倍以上：进度变化×1.5
  - 攻击方实力是防守方0.5倍以下：进度变化×0.7
- **FR-007**: 系统必须在决战模式下加速进度变化（×1.5倍）

#### 拉锯战机制

- **FR-008**: 系统必须支持占领进度的双向变化（攻击增加，防守减少）
- **FR-009**: 系统必须在占领进度降到0%时清除攻击方信息
- **FR-010**: 系统必须在占领进度达到100%时触发领土转移事件

#### 视觉反馈

- **FR-011**: 系统必须在地图上用渐变色显示占领进度
- **FR-012**: 系统必须在领土详情面板显示占领进度百分比
- **FR-013**: 系统必须在战斗日志中显示进度变化

#### 稳定性联动

- **FR-014**: 系统必须在占领进度增加时降低领土稳定性
- **FR-015**: 系统必须在领土完全占领后逐渐恢复稳定性

### Key Entities

- **ConquestProgress**: 占领进度数据结构
  - `territoryId`: 领土ID
  - `attackerId`: 攻击方ID
  - `progress`: 当前进度（0-100）
  - `lastBattleTime`: 最后战斗时间
  
- **Territory** (扩展): 
  - `conquestProgress`: 占领进度（0-100）
  - `contestedBy`: 正在争夺的势力ID（可为null）

## Quality Guardrails

- **Code Quality**: 新增代码需通过 ESLint 检查，遵循现有代码风格，使用 TypeScript 严格类型
- **Testing Evidence**: 为占领进度计算逻辑编写单元测试，覆盖率目标 80%
- **User Experience**: 渐变色显示需在低端设备上流畅运行（60fps）
- **Performance & Observability**: 占领进度计算不应增加超过 2ms 的 tick 处理时间

---

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 80% 的领土转移需要至少 2 次战斗才能完成（而非 1 次）
- **SC-002**: 边境地区出现拉锯战的概率达到 30%（进度在 30%-70% 之间波动超过 3 次）
- **SC-003**: 大国（面积>100万km²）平均需要 5+ 次战斗才能被完全占领
- **SC-004**: 玩家能在地图上直观识别正在被蚕食的领土（用户测试通过率 90%）

---

## Assumptions

1. **假设**：现有的 `Territory` 类型可以扩展新字段而不破坏现有功能
2. **假设**：渐变色渲染在 PixiJS 中可以高效实现
3. **假设**：用户更喜欢渐进式征服体验而非快速占领
4. **假设**：决战模式下仍然适用渐进式蚕食，但速度加快

---

## Out of Scope

- 领土分割（一个国家被分成多块分别占领）
- 傀儡国/附庸国机制
- 游击战/叛乱机制
- 和平条约/停战协议
